# 三线程并行任务分配

更新时间：2026-05-10

这份文件用于把后续重构拆给三个并行线程执行。目标是让三个人同时推进，但尽量不产生文件冲突。

主管原则：

1. 只有 1 号线程可以改公共注册点和构建文件。
2. 2 号和 3 号线程只新增独立模块，不接入公共构建，不改 route registry。
3. 三个线程都不能启动虚拟盘 runner，不能提交 OKX 订单。
4. 除 UI 和过渡 Python 壳层外，交易核心继续按 C++20 推进。
5. OKX 是当前唯一券商方向。

## 1. 总体边界

所有线程都必须遵守：

- 不改 `config/default.cfg`。
- 不改 `logs/`。
- 不改启动/关闭脚本。
- 不自动启动虚拟盘。
- 不提交 OKX 模拟盘或真实盘订单。
- 不引入 Rust。
- C++ 使用 C++20。
- 改完后说明：改了哪些文件、为什么、怎么验证、还剩什么没接入。

## 4. 3 号线程：OKX Gateway 设计骨架负责人

### 4.1 任务目标

先做 C++ OKX gateway 的接口骨架和数量折算设计，不接真实网络请求。

### 4.2 允许新增或修改的文件

### 4.3 具体目标

- 定义 simulated trading 专用 gateway 接口。
- 明确支持 `SWAP` 和 `FUTURES`。
- 明确 OKX 是唯一券商。
- 设计 `minSz / lotSz / ctVal / tickSz` 的数量和价格折算函数。
- 设计 OKX 原始失败码结构，例如 `code / msg / sCode / sMsg`。
- 只做接口和本地纯函数。
- 不发 HTTP。
- 不下单。
- 不撤单。

### 4.4 验收命令

### 4.5 禁止事项

- 不改 Python OKX 逻辑。

## 5. 主管集成顺序

建议集成顺序：

1. 先集成 1 号线程，因为它会改公共路由和构建文件。
2. 再检查 2 号线程的 market read model，统一接入 `Makefile`、`CMakeLists.txt` 和 `/api/backend/market/quality`。
3. 最后检查 3 号线程的 OKX gateway 纯函数和接口，统一接入构建和后续模拟盘执行链路。

这样可以避免三个人同时改同一个公共文件。
